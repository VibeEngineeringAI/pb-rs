# Retained phase 3 redirect deadline: proposed normalization

Status: **accepted by independent round-2 review for shared harness promotion**, no production change. Pinned Go 07af390/go1.25.4, preserved executable fae8411febf8603e7f73803ac81ab6e7303dfe9305247f0be9f9767bea262314.

Actual full60s `p3-deadline-spans-redirects` reference runs produced different errors after the same POST /api/v1/query then POST /v2/api/v1/query, exit1, ~60.06s, no stdout: first bare `context deadline exceeded`; second `net/http: request canceled (Client.Timeout exceeded while awaiting headers)`. Rust release1 produced `context deadline exceeded (Client.Timeout exceeded while awaiting headers)` at60.004s. Raw evidence is in `evidence/phase7/p3-redirect-deadline/`; original report/captures remain untouched in the phase cache.

Source cause: `pkg/http/http.go` wraps http.DefaultTransport in cloudRefreshTransport, unknown to Go net/http's knownRoundTripperImpl. Pinned Go `src/net/http/client.go:setRequestCancel` therefore installs both a context.WithDeadline and a timer goroutine with atomic timedOut. The context may terminate RoundTrip before the timer goroutine stores true. Client.Do adds the awaiting-headers suffix only when didTimeout() returns true. Both observed strings are valid outcomes at the same deadline. This is not an earlier independent context timeout: the fixture CLI passes none, and the two recorded requests both delay35s.

Proposed change only to `harness/phase3.py:normalize_timeout` and regression tests: when `compare.timeout_cause` is true AND case.name is exactly `p3-deadline-spans-redirects` AND the entire already URL-normalized stderr equals `Error: request execution failed: Post "http://<FIXTURE>/v2/api/v1/query": context deadline exceeded\n`, append ` (Client.Timeout exceeded while awaiting headers)` before existing TIMEOUT_CAUSE cause normalization. All other bytes/cases/paths/methods untouched. The existing independent reference expectations retain exit1, the ordered two-request method/path graph, no unexpected requests, and 59–70s duration. Request bodies/headers, stdout digest and semantic configuration are reference/candidate differential checks, not independent reference pins. The exact whole-error match supplies the second-hop error boundary; the synthetic suffix alone is not evidence of a timeout. No global optional suffix, error-category relaxation, corpus deletion or production timeout change.

Before promotion: independent review, targeted positive/negative tests, retained-artifact reduction, and fresh actual Go controls. Subsequent final Rust replay remains required. The original failed report must be retained and clearly distinguished from any reduction or rerun.
