File behavior and delivery guarantees to account for
  • Discovery: quoted globs are expanded by pb repeatedly, so new matching files join the session. Include and exclude rules belong in the collector.
  • Append semantics: ingest existing content or start at EOF; thereafter follow appends. Handle file rotation, truncation, and restart checkpoints. Rewritten source/config diffs are outside this first scope.
  • JSONL: wait for a newline before emitting a record. Preserve JSON fields, add collection metadata in a reserved envelope, and define a visible policy for malformed complete lines.
  • Delivery: batch and retry uploads; advance delivery offsets only after server acknowledgement. Retries may duplicate events, so stable event IDs and deduplication matter. Do not promise exactly-once delivery.
  • Limits: cap batch bytes as well as event count, define oversized-record handling, and bound any local retry spool. This demo models event count only.


Observation and completion: decisions still open
  • Cursor contract: the demo uses a position in an in-memory event list. Real cursors need stable ordering, late-arrival handling, and recovery across multiple files. A source sequence is not automatically a server-wide cursor.
  • Server scope: existing APIs cover basic ingestion and querying. Reliable resumable observation needs validation against those APIs; guaranteed resumable subscriptions may require server work.
  • Review acknowledgement: saving progress after agent review avoids silently skipping an unprocessed batch. The CLI interface and crash recovery behavior need to be specified.
  • Waiting: the proposed wait is bounded. Empty reads return immediately in this demo; a real call could wait up to 10 seconds.
  • Completion: silence is not completion. The last scenario step simulates an explicit run-end signal after uploads flush. An observer finishes only after it has also reviewed the remaining events. The signaling interface is not yet designed.
