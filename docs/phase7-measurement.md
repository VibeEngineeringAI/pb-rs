## Shared observer seams and definitions

The published backward-compatible keyword-only APIs are used directly:

- `sample(..., execute_fn=None)` and `observer_floor(..., execute_fn=None)` inject the shared executor. Floor acquires no lock; it runs inside the single collector-held lock.
- `execute(..., proc_sampler=None, continue_running=None, readiness_fn=None, observer_config=None, spawn_helper_build=True)` retains native fork/PTY/wait4 and emulator ownership. Deadline callback returns None to continue or a failure string to kill/reap while retaining the invalid result.
- `record_termios`/`record_chunks` default true. Minimal controls disable the root resource sampler and those optional histories, and require shared `record_descendants=False` to disable periodic descendant `/proc` traversal. Protocol identity checks and termios readiness/final snapshots remain: minimal is not a claim of zero observer work. `record_descendants` defaults true and changes periodic sampling only; final cleanup checks remain enabled. The published interface accepts it; disabling descendant sampling makes isolated child attribution ineligible, while final cleanup still runs.
- Both Capture and ProfileCapture pass `spawn_helper_build=False`. Shared execute resolves with `spawn_helper(build=False, probe=False)`: no compiler-version/capability subprocess, compile, cache repair or write is allowed on this capture path. The initial `cached_spawn(probe=True)` calls the shared resolver with `build=False` before QuietWindow to prepare compiler-version and capability snapshots; per-role verification uses `probe=False`. Preparation overhead is excluded from child lifecycle elapsed and is not claimed absent. A missing helper or preparatory snapshot fails closed before CLI/PTY acquisition.
- Frame stamps retain `stable_since_monotonic_ns`, the beginning of the actual unchanged qualifying styled-frame interval.

First useful startup is the observer's pre-spawn CLOCK_MONOTONIC stamp to the first-ever observation satisfying target text/cells and raw/alternate state. `first_useful_monotonic_ns == first_ever_match_monotonic_ns` survives later predicate flicker; `stable_since_monotonic_ns` independently marks the eventual unchanged qualifying interval. Timestamp ordering is a sanity check, not old-frame protection. Input-to-expected begins at **event.dispatch_monotonic_ns**, taken immediately before the encoded key/send os.write, or after local emulator resize immediately before ioctl/SIGWINCH. It excludes observer readiness/frame/digest/snapshot work. The legacy monotonic_ns and explicit evaluated_monotonic_ns remain the earlier evaluation stamp; neither is a latency origin. New measured actions have exactly one dispatch type and missing/ambiguous dispatch stamps fail closed. This includes write/ioctl cost; it is not an exact child input receipt timestamp. Input-to-stable uses that origin to acceptance after the entire qualifying styled frame (cells, attributes, cursor and scrollback) stays unchanged for at least **80 ms**. First-expected, stable-begin and acceptance stamps remain separate. The 10 ms observer poll is included, not pure reducer latency. Runtime screen waits contain no fixture request-path/count predicates, so the 50 ms trace IPC poll no longer gates first-useful or stability.

`cli_lifecycle_elapsed_ms = (reaped_monotonic_ns - started_monotonic_ns)/1e6` is validated finite/positive and included in paired summaries. With native helper protocol 2, legacy `reaped_monotonic_ns` aliases the actual exited stamp; the metric is observer pre-spawn-to-native-exit elapsed, including startup, scripted waits, stability holds and idle. `native_wait4_reaped_monotonic_ns` records the later gated wait4 and is never used as session latency. It is not pure compute time. Native user/system CPU remains child wait4 rusage and is never derived by subtracting elapsed components.

Scroll readiness requires changed `rows N/TOTAL` and a unique loaded row marker. Resize requires new dimensions, a corner at the new right edge, fresh child output, and cells differing from the simulated post-resize snapshot. The snapshot copies only pyte main/alternate screen state and applies the same resize before dispatch; stream generators are never copied. Geometry truncation and cursor-only output both fail. Editor readiness requires changed SQL text. Dense metrics table/chart switches require the explicit new `Table View`/`Chart View` target. Network phases require loaded rows at runtime. After capture, request paths/counts are validated against milestone receipt timestamps at or before that phase's first-ever target observation. Future requests cannot satisfy earlier phases. Cache-hit cases require exactly one offset-zero request for the whole session; merely sharing a refetch bug cannot pass the independent expectation. Idle is an elapsed interval between valid checkpoints, independent of cursor blinking.

SQL fixtures return exactly the requested slice: LIMIT at most 500, OFFSET multiple of 500, explicit final smaller slice if applicable. Closing-quote body matching prevents OFFSET 500 from matching 5000. The 20,000-row case requires windows 0→500→1000→1500 and a second zero-offset fetch, demonstrating turnover of a three-window cache. The 500/1,500-row cases measure cached paging; they are not labeled turnover. The collector reads/hashes `performance_workloads` and keeps its response construction owned; historical oversized static responses are never labeled real window paging.

Native resources require `resource_source: native_child_wait4`, helper source/binary hashes and explicit descendant attribution. Setup/exec errors and unavailable resource counters are invalid, never genuine zero. Nonempty observed descendants are retained and make isolated CLI CPU/RSS triggers ineligible. `phase7_spawn.c` is included in source/harness provenance and helper metrics retain compiler/flags/hash/PIDs. Sampled VmHWM is separately reported as a post-exec lower bound. Child wait4 final context switches cover the whole child. Sampled `/proc/PID/status` context switches cover the **main thread only**, not task-group totals; idle reports carry that scope explicitly. Sampled RSS, FD counts, faults, CPU ticks and IO are separate from wait4 peak RSS. Proc IO excludes unsampled tails and retains boundary coverage gaps; it is not exact final filesystem/socket IO. Missing counters/errors invalidate measurements rather than becoming zero. Native block-input/output operations are operation counts, not bytes. Idle entries record `tick_resolution_pp = 100/(CLK_TCK * sampled_seconds)` and a two-tick endpoint bound. Short idle CPU is descriptive; only explicitly named long-idle phases with descendant attribution are eligible for the 0.25 pp investigation policy. Genuine zero counters remain valid and give absolute deltas with undefined ratio when the reference is nonpositive. Observer SELF CPU/RSS is separate; its peak RSS is explicitly observer-lifetime, not a fresh session peak. Fixture CPU is excluded from CLI/observer counters and is not measured by this collector.

Primary runs use `--observer-policy primary`: keep native_proc_sample and essential PTY/emulator/readiness/deadline/raw-stream/native-wait4 work, set record_termios/chunks/descendants=False. Definitions, preflight and captures record this exact policy. Current known-emitter pairs match primary observation against floor-minimal: both disable optional histories/traversal, only primary retains the root sampler. Tiny and representative controls remain separate, with unchanged session counts and no latency subtraction. Historical full/minimal plans/results remain retained; resource-attribution campaigns instead pair their explicitly selected attribution policy against minimal, retaining that distinct label. Primary resource counters remain validated/descriptive; descendant_comparison_eligible=False forbids isolated CPU/RSS and idle investigation triggers even when observed_descendants is empty. `--observer-policy resource-attribution` is a separate harness-only session class with root sampling and descendant observation enabled, optional histories still off, and a distinct name/definition suffix. Isolated CPU/RSS triggers additionally require the shared eligibility flag true and no observed descendants; idle triggers also require a declared long interval. Missing counters are still invalid.

The tiny-frame floor is labeled as such. A second matched control replays a validated Go startup byte stream before each numbered marker; the payload/session hashes and source case are retained, and reply bytes are drained until the explicit acknowledgement. It exercises representative SGR decoding/full-frame hashing without claiming a pure reducer baseline. Both emitters have randomized primary/minimal controls matched by size/theme and reported separately, never automatically subtracted from CLI latencies. Frames inside one session are descriptive observations, not independent replicates. Independent paired rounds feed the existing seeded session/paired bootstrap routines; p95/p99 at small session counts remain descriptive. No universal faster claim or performance acceptance budget is invented. Prior Rust has no interactive comparator here: parent owns shared noninteractive phase1–5 regression collectors.
