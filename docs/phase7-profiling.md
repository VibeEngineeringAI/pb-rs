## Capture semantics and diagnostics

`phase7.sample(actual_binary, ..., execute_fn=...)` seeds each independent fixture/config and retains the actual binary identity. Controls use the shared `Capture`; instrumented execution prepends `profile_external.command` argv at the shared execute boundary. The report and raw capture retain the complete intercepted command, actual CLI argv, profiler prefix/identity, binary SHA/source provenance, actual isolated environment and scope labels. No shell interpolation of CLI arguments is used.

External perf/strace diagnostics are redirected by a small argv-preserving shell launcher to `profiler.stderr`. The CLI shim restores original stderr from inherited FD3 and closes FD3 before native exec. CLI stderr stays in `capture/stderr.bin` and participates in exact comparison. This depends on the profiler preserving inheritable FD3; a profiler that closes it fails the retained functional/lifecycle contract. External diagnostic files are required even when empty; absence is a failed separation contract. Raw diagnostics are preserved verbatim with their own identity; warnings are not silently relabeled CLI output or removed by pattern normalization. Denied perf is labeled unavailable when the first bounded 64 KiB of its explicit diagnostic contains permission/paranoid denial and the capture/artifact fails. Nonempty warnings alongside successful artifacts remain visible to the parent for interpretation.

Heaptrack uses `/usr/bin/env LD_PRELOAD=<library> DUMP_HEAPTRACK_OUTPUT=<path> <actual Rust binary>` from the existing helper. No preload enters a shell or Go process. Preload diagnostics share native stderr in-process; **no filtering** occurs, and any deviation from the uninstrumented stderr contract fails comparison. Heaptrack native allocator hooks/raw recording are incomparable to Go's managed heap; there is no Go heaptrack row or managed-heap claim.

Cases, screen readiness and independent expectations reuse the collector. Each control must validate, and symbolized/release styled cells, causal requests, configuration, streams and lifecycle must match the Go release control. Each instrumented capture must match its own uninstrumented symbolized control with the same exact comparator. Failed controls stop dependent captures. Instrumented failures are retained and other planned tools may continue while the guard remains valid. No statistical timing summary is produced.

External profiler wrapper PID is the supervised native child; the descendant pb PID is explicitly unknown. Heaptrack env exec retains the same PID. Reports record that mapping/scope; no PID-specific pb attribution is inferred from wrapper proc samples. All instrumented wait4/proc resources are labeled profiler/wrapper process-tree or Rust allocator-hook overhead; they are never native uninstrumented CLI measurements. Perf includes shell exec/startup and profiler costs. The attribution report does not subtract these costs or claim release speedups. Native helper rusage boundaries remain shared harness ownership. The driver requires a prebuilt matching helper, records its source/binary hashes in the definition, and rejects helper changes rather than triggering a build. Protocol 2's exited stamp defines lifecycle elapsed; gated wait4 time is not latency. Native helper review must be accepted before actual captures. Initial compiler-version/capability preparation runs before QuietWindow; per-role verification is `cached_spawn(probe=False)`. Both the uninstrumented Capture and profiler adapter use `execute(..., spawn_helper_build=False)`, which resolves with `build=False, probe=False` and cannot spawn compiler/probe processes or build/repair/write if the cache disappears. Missing helper/preparation fails closed before PTY acquisition. Preparation overhead is outside lifecycle elapsed; native cleanup can overrun an active deadline by about eight seconds, with fixture/evidence work outside the child loop.
